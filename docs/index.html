🧭 Total app ela pani chestundhi (how the whole thing works)

1
Signup → UID + recovery file.

User creates an account with password + PIN. App generates a UID-XXXXXXXXXX identity and forces download of an encrypted .crestline recovery file (E2EE export). No email/phone — the file + credentials ARE the account.

2
$20 USDT deposit = VIP pass.

App shows the pool wallet address and a reserved deposit bucket. User sends exactly $20 USDT from their own wallet. The app watches ERC-20 Transfer logs on the chain, recognizes the new valid deposit, locks that sender wallet to the account (same-wallet policy, 1 wallet = 1 person) and replay-protects the tx hash so one tx can't be claimed twice.

3
Daily login & 28-day claims.

After VIP activation, user checks in daily. The 28-day claim schedule accrues daily income to the in-app balance; missed days don't double-pay. Chain clock (block timestamps) is used, so device-clock cheating is limited.

4
Referrals.

Each user gets a referral code. A referral only counts when the joined friend makes their own valid $20 deposit and first claim (validity gate) — no deposit, no credit.

5
Withdrawal: $15 → $13.80.

When balance reaches $15, withdrawal permission unlocks. An 8% fee applies, so the user receives $13.80, paid back only to the same locked wallet. Below $15, every withdrawal path is rejected.

6
Logout / lost device → import.

Logging out or wiping the device is fine: importing the .crestline file + credentials restores the full account on a new device. A no-file “Time-Cipher” (TC1) recovery path also exists.

7
Admin side.

Admin builds boot to an owner passcode lock (6-char code derived from the master seed). Recovery tabs: direct seed or 2-of-3 guardian shares. Wrong seed/code is rejected. The console behind the lock manages pools/payouts — it stays locked without the owner code.

8
Android wrapper.

Each build also ships as a native Android APK (WebView + WebViewAssetLoader, FLAG_SECURE, JS bridge, deep links). 4 signed QA APKs exist in the GitHub release v1.0.0-qa.

⚙️ Known issues on this hosted version

  • Live RPC needed: user apps call Polygon RPCs from the browser; if an RPC is unreachable the app can hang at “Loading Crestline VIP…” (known defect — no offline/timeout UI).
  • Testnet build: default RPC rpc-amoy.polygon.technology does not resolve and USDT_ADDRESS is empty — deposits fail with “USDT token contract address is not configured for this network.” unless a ?usdt=0x… override is used.
  • This is a static host: no backend; all state lives in your browser (localStorage) + the chain.
